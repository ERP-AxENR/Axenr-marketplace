# /axenr-dev:sync-lessons

Pousse les lecons accumulees localement (LOCAL-LESSONS-<hostname>.md) vers le fichier partage `LESSONS-LEARNED.md` du marketplace, en passant par une Pull Request pour review.

## POURQUOI

Chaque developpeur accumule des lecons dans son `LOCAL-LESSONS-<hostname>.md` (gitignore). Cette commande :
- Lit le LOCAL file
- Pour chaque lecon, interroge `lesson-deduplicator` contre `LESSONS-LEARNED.md` (partage)
- Fusionne les matches, ajoute les vraies nouvelles
- Ouvre une PR pour que le curateur review avant merge
- Apres merge, un `/plugin update` chez les autres devs propage les nouvelles lecons

Consequence : les lecons restent locales jusqu'a consolidation humaine. Pas de push direct vers la base partagee.

## ETAPES

### Etape 0 : Pre-flight

```bash
cd <marketplace_path>
git status --porcelain
```

Refuser si working tree non propre (stash requis).

### Etape 1 : Detecter le fichier LOCAL

```bash
LOCAL_FILE="plugins/axenr-dev/docs/lessons/LOCAL-LESSONS-$(hostname -s).md"
```

Si le fichier n'existe pas ou est vide, sortir avec message "Aucune lecon locale a synchroniser".

### Etape 2 : Parser les lecons LOCAL

Extraire tous les blocs `### LESSON-LOCAL-XXX` du fichier local.
Pour chaque bloc : lire Type, Source, Rule ID, Erreur, Regle, Occurrences, Tickets, Date.

### Etape 3 : Dedupliquer contre le fichier partage

Pour chaque lecon locale :
- Normaliser la signature (meme logique que lesson-deduplicator)
- Appeler lesson-deduplicator contre `LESSONS-LEARNED.md` (partage)
- Selon la decision :
  - `increment` -> preparer un patch qui incremente Occurrences + ajoute Tickets de la lecon existante
  - `review` -> listerr en section REVIEW-QUEUE avec candidates
  - `new` -> preparer l'ajout en nouvelle `LESSON-NNN` (ID suivant le compteur global)

### Etape 4 : Proposer le resultat au dev

Afficher :

```
Synthese /axenr-dev:sync-lessons :
- Lecons locales : N
  - a incrementer : X (mergees dans des existantes)
  - en review : Y (ambiguites -> REVIEW QUEUE)
  - nouvelles : Z (LESSON-NNN -> LESSON-MMM)
- Promotions declenchees apres merge : P (lecons qui atteindront 3+ occurrences)
```

Si `--dry-run`, stopper ici. Ne RIEN ecrire.

### Etape 5 : Backup + ecriture sur branche dediee

```bash
BRANCH="lessons/sync-$(hostname -s)-$(date +%Y%m%d-%H%M%S)"
git checkout -b "$BRANCH"
cp plugins/axenr-dev/docs/lessons/LESSONS-LEARNED.md plugins/axenr-dev/docs/lessons/LESSONS-LEARNED.md.bak-presync
```

Appliquer les patches calcules en Etape 3 sur `LESSONS-LEARNED.md`.

Mettre a jour l'en-tete STATS.

### Etape 6 : Commit

```bash
git add plugins/axenr-dev/docs/lessons/LESSONS-LEARNED.md
GIT_COMMITTER_NAME="fbe-axenr" GIT_COMMITTER_EMAIL="f.benomar@erp-axenr.fr" \
  git commit --author="fbe-axenr <f.benomar@erp-axenr.fr>" \
  -m "chore(lessons): sync $N lessons from $(hostname -s)

- $X incremented
- $Y in review queue
- $Z new lessons

Auto-generated by /axenr-dev:sync-lessons"
```

### Etape 7 : Push + PR

Si `--auto-pr` :

```bash
git push -u origin "$BRANCH"
gh pr create \
  --title "chore(lessons): sync lessons from $(hostname -s)" \
  --body "$(cat <<EOF
Synchronisation automatique des lecons locales.

## Resume
- Lecons locales synchronisees : $N
- Incrementations : $X
- En review : $Y
- Nouvelles lecons : $Z
- Promotions attendues apres merge : $P

## Procedure
- Review le diff (surtout les nouvelles lecons)
- Pour les lecons en REVIEW QUEUE, trancher avec /axenr-dev:consolidate-lessons
- Merge -> les autres devs font /plugin update pour recuperer

Auto-generated by /axenr-dev:sync-lessons
EOF
)" \
  --base main
```

Sinon, afficher les commandes `git push` et `gh pr create` pour que le dev les lance.

### Etape 8 : Nettoyage local

Apres push reussi, vider le LOCAL file (mais garder un backup) :

```bash
cp "$LOCAL_FILE" "${LOCAL_FILE}.bak-synced-$(date +%Y%m%d-%H%M%S)"
cat > "$LOCAL_FILE" <<EOF
# Local Lessons - $(hostname -s)

> Fichier local, non commite. Accumule les lecons de ce poste uniquement.
> Synchronise vers LESSONS-LEARNED.md via /axenr-dev:sync-lessons.

## LECONS

(vide - nouvelles lecons apparaitront ici)
EOF
```

## INTERACTION AVEC /plugin update

Flow complet cote equipe :

```
Dev Alice             Agent Alice            GitHub           Dev Bob
    |                      |                    |                |
    |-- solve ticket       |                    |                |
    |                      |-- write lesson --> LOCAL-LESSONS-alice.md
    |                      |                    |                |
    |-- /axenr-dev:sync-lessons                     |                |
    |                      |-- dedup vs SHARED  |                |
    |                      |-- open PR -------->|                |
    |                                           |                |
Curator (Fabien)                                |                |
    |-- review PR + merge --------------------> |                |
    |                                           |                |
    |                                                            |-- /plugin update
    |                                                            |   (pulls merged lessons)
```

## FAQ

**Q : Que se passe-t-il si deux devs syncent en meme temps ?**
R : Branches separees par hostname. La 2e PR verra les nouvelles lecons de la 1ere deja
mergees et appliquera la dedup par dessus. Zero conflit Git sur LESSONS-LEARNED.md.

**Q : Pourquoi pas un push direct sans PR ?**
R : Curator model. On veut que Fabien/toi relise avant que la lecon fasse loi pour tous.
Evite la pollution par des faux patterns detectes une fois.

**Q : Les backups des LOCAL sont gardes combien de temps ?**
R : Indefiniment (gitignored). A l'utilisateur de nettoyer periodiquement.
